{%- comment -%} Page-specific JSON-LD, in addition to the generic tags jekyll-seo-tag emits: / -> ResearchOrganization (the lab) /pi/ -> Person (the PI) /publications// -> ScholarlyArticle (a paper with a DOI or preprint) + BreadcrumbList /people// -> Person + BreadcrumbList /publications/ /members/ /alumni/ -> CollectionPage with an ItemList of the collection All values come from the same _data files the pages render from, so the structured data cannot drift from the visible content. Invisible to sighted users (metadata). The lab and the PI carry stable "@id"s (/#organization, /pi/#person), and the other mentions of them in this file repeat that @id (the home page's founder, a person's worksFor or alumniOf, and the PI in a paper's author list, matched on pi.yml `name` or `name_full` as the bold PI name is), so search engines join the mentions into one lab and one person. jekyll-seo-tag's own block names the lab without an @id. sameAs lists only profiles of the entity itself: the PI's Scholar and ORCID pages sit on the PI, never on the lab. {%- endcomment -%} {%- capture orgref -%}{"@type":"ResearchOrganization","@id":"{{ site.url }}/#organization","name":{{ site.title | jsonify }},"url":{{ site.url | jsonify }}}{%- endcapture -%} {%- if page.url == "/" -%} {%- elsif page.url == "/pi/" -%} {%- elsif page.pid -%} {%- assign p = site.data.publications | where: "id", page.pid | first -%} {%- if p -%} {%- comment -%}ScholarlyArticle only for a paper with a public version (DOI or preprint), the same rule as citation-meta.html: a manuscript under review is not yet an article in a periodical ("Submitted" is not a journal).
