{%- comment -%}Journal-covers highlights section (home + photos pages). Renders nothing when there are no covers. Each cover opens a fullscreen viewer (viewer.js, dialog from lightbox.html) that loads a high-res "-full.jpg" rendition; the thumbnail stays small for fast loading. Progressive enhancement: the cover is a real link to the paper for no-JS users and crawlers, and viewer.js intercepts the click to show the full cover (with a paper link inside). Pages that include this must load viewer.js (front matter: scripts: [viewer]). The full-size name drops only the LAST extension ("a.v2.jpg" -> "a.v2-full.jpg"), the same rule the data validator checks. When CI made a smaller rendition of the thumbnail (see image-srcset.html), the browser may pick it; the `sizes` value is the cover's width: five to a row from 685px, three from 405px, two below, with a 20px gap inside .container (1140px max, side padding clamp(1.1rem, 4vw, 2rem)), so 199px from 1140px. Checked against the drawn width at every viewport width from 320 to 1600px.{%- endcomment -%} {%- assign covers = site.data.covers -%} {%- if covers and covers.size > 0 -%}
